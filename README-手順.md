# 編成のサーバー同期 ― 入れ方

運行図表の「運用表」で入れた編成を、端末ごとの保存からサーバー保存に変える変更です。
臨時列車の事前登録と同じ仕組み(GAS + 通行証)を使います。

- 見る側: ログインしている全員が、その日の編成を自動で受け取ります。
- 入れる側: 「管理者」列に ○ が入っているIDだけが、編成をサーバーへ送れます。
- 編成は日付ごとに保存されます。昨日の編成が今日に残ることはありません。
- 同期の対象は「今日のダイヤ(平日/休日)」の編成だけです。もう一方のダイヤの入力は、今まで通りその端末だけに残ります。

## 変更するファイル

| ファイル | 内容 |
|---|---|
| `Formations.gs` | 新規追加(GAS) |
| `Extras.gs` | doPost の switch に2行追加 |
| `upload.html`(運行図表) | 差し替え(再暗号化が必要) |
| `viewer.js` | 差し替え |

`index.html` と `admin.html` は変更しません。

## 手順

### 1. GAS(Apps Script)

1. プロジェクトに新しいファイル `Formations.gs` を作り、同梱の `Formations.gs` の内容を丸ごと貼ります。
2. `Extras.gs` の `doPost` の switch を、下のように書き換えます(2行追加)。

   変更前:
   ```js
      case 'extras': return out_(extrasGet_(req));
      case 'xlist': case 'xput': case 'xdel': return out_(extrasAdmin_(req));
   ```
   変更後:
   ```js
      case 'extras': return out_(extrasGet_(req));
      case 'xlist': case 'xput': case 'xdel': return out_(extrasAdmin_(req));
      case 'fget': return out_(formationsGet_(req));
      case 'fput': return out_(formationsAdmin_(req));
   ```
3. `setupFormations` を一度だけ実行します(「編成」シートが作られます)。
4. ウェブアプリを「新しいバージョン」でデプロイし直します(URLは変わりません)。

### 2. GitHub Pages

1. `viewer.js` を同梱のものに差し替えます。
2. `upload.html` を同梱のものに差し替えて、いつもの手順で再暗号化し、`data/diagram.enc.json` を更新します。
   (`monitor.enc.json` は変更しません)

### 3. Muse 用IDの管理者設定

編成を送れるのは管理者IDだけです。「ユーザー」シートの「管理者」列(I列)で、
Muse 用ID(`mu-7958`)の行に ○ を入れてください。これがないと、Muse のブラウザからの
入力はサーバーに保存されません(見るだけになります)。

## 動作

- ページを開くと、その日の編成がサーバーから自動で図表に入ります(トーストで知らせます)。
- 管理者の端末で編成を入力・変更すると、数秒でサーバーへ送られます。
- 開きっぱなしの画面は5分ごとに取り直すので、ほかの端末の変更も自動で反映されます。
- 編成は日付ごとに60日分だけ残り、古いものは保存操作のときに自動で消えます。
- サーバーに記録がない日は、今まで通り端末の入力が使われます(起動時にサーバーの内容で上書きされるのは、サーバーにその日の記録がある場合だけです)。

## 注意

- 図表側の「名前つき保存セット」は今まで通り端末ごとの機能です。サーバー同期とは別に動きます。
- 運用表で「編成をすべて消す」を押すと、その日の編成が空になるため、管理者の端末ではサーバー側も空になります。
